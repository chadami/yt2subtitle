系统分为三层：浏览器扩展层（用户交互 + 字幕提取 + 叠加显示）、后端 API 层（身份认证、任务管理、数据访问）、Worker 层（异步字幕翻译流水线）。通过 Redis/BullMQ 实现 API 与 Worker 的解耦。

浏览器扩展采用 MV3 架构：Content Script 注入 YouTube 页面负责字幕提取和叠加显示；Background Service Worker 负责 API 通信、任务轮询、本地缓存和桌面通知；Popup 和 Options 页面提供用户交互界面。三者通过 chrome.runtime.sendMessage 通信，数据存储在 chrome.storage.local 中。

6. 字幕处理流水线状态图 (Subtitle Pipeline States)

stateDiagram-v2 [*] --> Queued: 任务入队 state Queued { description 等待 Worker 领取 } Queued --> Cleaning: Worker 领取任务 state Cleaning { description 进度 10% stripSpeakerMarker: 去除说话人标记 resolveOverlaps: 解决时间重叠 prepareSourceCues: 标准化原始字幕 autoCaptionGroup: 自动字幕分组(ASR) } Cleaning --> Translating: 清洗完成 state Translating { description 进度 25% ~ 80% analyzeContext: 分析视频上下文(话题/术语表) chunkCues: 按字符数分块 translateChunk: 逐块调用 AI 翻译 saveChunks: 保存 chunk 到 DB } Translating --> Finalizing: 所有块翻译完成 state Finalizing { description 进度 95% groupBySourceTiming: 按原始时间分组 enforcePunctuationSegmentation: 按标点断句 enforceReadableDurations: 确保可读时长 enforceSubtitleLimits: 字数/时长限制 addContinuationPunctuation: 补充标点 toVtt: 生成 VTT 格式 } Finalizing --> Completed: 持久化完成 state Completed { description 进度 100% saveSubtitles: 保存到 translated_subtitles notifyUser: 邮件 / 浏览器通知 } Cleaning --> Failed: 清洗失败 Translating --> Failed: 翻译失败(重试耗尽) Finalizing --> Failed: 后处理失败 state Failed { description 记录 error markFailed: 更新状态 + error } Completed --> [*] Failed --> [*]

翻译任务状态机：Queued → Cleaning（字幕清洗）→ Translating（AI 翻译，含分块逐块处理）→ Finalizing（时间轴校准 + 字数/时长限制 + 标点断句）→ Completed。任何阶段失败且重试耗尽则进入 Failed 状态。
