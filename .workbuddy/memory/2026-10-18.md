# 2026-10-18

## 把后端本机化，做成 macOS 原生 App（免 Docker）

**目标**：用户不想用 docker 跑本地后端，希望一个 macOS App 里填 API Key，App 负责与 Chrome 插件通讯。

**后端改动（`LOCAL_MODE=1` 分支，云端 SaaS 形态保留）**
- `backend/src/db.ts`：Postgres / PGlite 双实现。PGlite 是单连接，用 Mutex 串行化；`db.connect()` 持有锁直到 `release()`，避免 BEGIN/COMMIT 与其它请求交错。
- `backend/src/localQueue.ts` + `queue.ts`：本机用进程内队列替换 BullMQ；`queue.ts` 用 top-level await 动态选择实现，避免本机加载 bullmq/ioredis。
- `backend/src/jobRunner.ts`：从 `worker.ts` 抽出的任务处理逻辑，新增 `runSubtitleJobInProcess`（自带重试）。
- `backend/src/auth.ts`：`LOCAL_TOKEN` → 固定本地匿名用户 `local-device`，不走邮箱验证码。
- `backend/src/routes/local.ts`：`GET /api/local/session` 返回本机令牌，`GET /api/local/status` 返回队列/任务/AI 配置。
- `backend/src/routes/ai.ts`：本机模式的 Key 来自 `LOCAL_AI_*` 环境变量；`POST /api/ai/settings` 在本机模式返回 400，提示去 App 配置。
- `backend/src/env.ts`：本机模式下 `DATABASE_URL/REDIS_URL` 可选，JWT secret 持久化到 `DATA_DIR/jwt-secret`。

**macOS App（`macos/`）**
- SwiftUI（SPM，非 Xcode 工程），`swift build -c release --disable-sandbox`（本机沙箱下必须加 `--disable-sandbox`）。
- 内嵌 Node 22 二进制 + 精简后端运行时（express/zod/jsonwebtoken/cors/PGlite）。
- 设置存 `~/Library/Application Support/VidLingo/config.json`，API Key 存 Keychain（service `com.vidlingo.desktop`）。
- 端口 3000，仅监听 127.0.0.1；菜单栏常驻；开机启动用 LaunchAgent。
- 打包：`npm run build:mac` → `dist/VidLingo.app` + `dist/VidLingo.dmg`（脚本内避免 `rm -rf` 大目录，改为移到废纸篓 + ditto）。

**插件改动（0.1.4）**
- `host_permissions` 改为 `http://127.0.0.1/*`、`http://localhost/*`（不限端口）。
- background/contentScript/options 增加本机自动登录（`/api/local/session`）与「使用本机应用」按钮。
- 设置页原先隐藏的 Backend API URL 段落改为可见。

**验证**
- 本机模式：健康检查、会话、匿名用户、任务创建（事务 + advisory lock）、进程内队列、失败重试均通过。
- 真实 DeepSeek Key 跑通 3 条 cue 的翻译，目标语言 zh-Hans，任务 completed 且返回双语 cues。
- App 启动后 `/api/local/status` 正常，轮询日志正常。

**产物**：`dist/VidLingo.app`（155M）、`dist/VidLingo.dmg`（63M）。

## 修复：每次重建都要输入系统密码

- 现象：每次 `npm run build:mac` 后打开 App，会连续弹多次"VidLingo 想要使用钥匙串中的机密信息"。
- 原因不是"把 Key 存进钥匙串"本身，而是**签名身份每次都在变**：之前用 `codesign --sign -`（ad-hoc），签名标识等于二进制哈希，重建一次就是一个"新 App"，钥匙串 ACL（designated requirement）对不上，于是重新要密码；一次启动要读 ai-api-key / local-token / jwt-secret（可能还有 google-api-key），所以是好几次。
- 修复：`build-app.sh` 自动挑选 `security find-identity -p codesigning` 里的 Apple Development 证书签名（当前 `Apple Development: junc92622@163.com (XW4F7KY8D3)`，Team `MDWTBXLL5K`），DR 变成 `identifier "com.vidlingo.desktop" and anchor apple generic and certificate leaf[subject.CN] = ...`，跨构建稳定。
- 验证：签名后启动，服务正常读取 Key（`/api/local/status` 显示 configured=true），未再阻塞。
- 注意：证书过期/更换会再次触发一次授权；ad-hoc 仅作为找不到证书时的兜底。
- 同时把新版覆盖安装到 `/Applications/VidLingo.app`。

## 补：端口占用与退出语义

- 重建后发现偶发"本机服务没响应"，日志是 `EADDRINUSE 127.0.0.1:3000`：用 `killall` 结束 App 时 AppKit 不执行 `applicationWillTerminate`，node 子进程变成孤儿继续占端口，新实例重试 5 次后放弃。
- 修 1（后端）：`server.ts` 在本机模式下对 `EADDRINUSE` 每 500ms 重试，最多 20 次（日志 `Port 3000 is busy, retrying (n/20)`）。实测冲突时确实进入重试，占用不释放才最终退出。
- 修 2（App）：AppDelegate 接管 SIGTERM → `NSApp.terminate`，并在退出时 `stopAndWait()`，避免孤儿进程。
- 现在 `killall VidLingo` 也能干净退出。

## 新功能：macOS 系统翻译作为机翻引擎

- 新增 SPM 可执行目标 `TranslateCLI`（`macos/Sources/TranslateCLI`），产物 `vidlingo-translate`，用 `Translation` 框架做英→中等翻译；stdin/stdout JSON。
- 关键 API：`TranslationSession(installedSource:target:)`（macOS 26+）可直接在无 UI 进程里创建会话；`LanguageAvailability.status(from:to:)` 返回 installed/supported/unsupported。
- 语言包未安装时 `installedSource` 初始化会抛 `notInstalled`，CLI 返回 `{"ok":false,"error":"not_installed","status":"supported"}`。**下载必须由 SwiftUI `.translationTask` + `prepareTranslation()` 触发系统弹窗**，CLI 无法自行下载。
- 后端：`LOCAL_MT_PROVIDER=off|google|macos`、`LOCAL_TRANSLATE_HELPER`；`MachineTranslationError` 带 HTTP 状态码；machine-preview 在 macos 模式下 spawn helper，未装包返回 409 `macos_language_not_installed`。
- App：`LocalTranslationInstaller`（configuration 存 Any? 以保持 macOS 13 部署目标）+ `TranslationInstallHost` 把 `.translationTask` 挂到 RootView；AI 页机器翻译卡片改为 关闭/本地(macOS)/Google 三选一，本地模式显示语言包状态与「下载语言包」按钮。
- 构建：`swift build -c release` 同时产出 app 与 helper，脚本复制到 `runtime/bin/vidlingo-translate` 并随包签名。
- 验证：应用内 `/api/local/status` 显示 provider=macos；machine-preview 返回 409 + 正确错误码。语言包尚未下载，实际翻译需用户点一次「下载语言包」后验证。

## 小修：顶部提示条不会消失
